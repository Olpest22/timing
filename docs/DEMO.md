# Сценарий показа (≈ 7 минут)

Подготовка: `docker compose up --build`, затем `docker compose exec server npm run db:seed:prod`.
Откройте два окна браузера: обычное и инкогнито (два разных пользователя). Пароль у всех — `demo123`.

## 1. Задача и идея (30 с)

> Команде из 8 человек нужно найти два часа на ретро. В чате это превращается в «могу в четверг, но
> не после шести». «Тайминг» собирает свободное время каждого и показывает, когда собраться.

Главная `http://localhost:5173`: живой табель. Нажмите несколько клеток — оттиск «Лучшее время»
пересчитывается. Наведите на карточку участника в стеллаже — табель показывает только его часы.

## 2. Организатор (1,5 мин) — окно 1, `anya@demo.timing`

1. **Кабинет:** «1 мероприятие ждёт вашей отметки», три ячейки: ждут ответов / назначено / прошли.
2. **«Ретро спринта»** (`/e/retro234`): бланк, срок «осталось N дней», часовой пояс.
3. **Вся команда:** тепловая карта, наведение — «свободны 5 из 8, может: …, не могут: …».
4. **Лучшее время:** три варианта; выбор обводит окно на карте.
5. **Звёздочка у Маши** (обязательная) уже стоит — объясните, что окна без неё отброшены; снимите
   звёздочку — варианты пересчитаются, верните.

## 3. Участник и живые обновления (1,5 мин) — окно 2, `sveta@demo.timing`

1. Света ещё не отметилась — открывается «Моё время».
2. Протяните мышью по четвергу 17:00–19:00 — отрезок, «Сохранено».
3. **В окне 1 без перезагрузки:** «Вся команда 8/8», карта и варианты обновились.
4. Кисть «Если очень надо» — пунктирный отрезок; ручки и крестик у отрезка под курсором.
5. Включите «Показать команду на фоне».

## 4. Назначение (1 мин) — окно 1

1. «Назначить: четверг, … 17:00–19:00» — оттиск «Время назначено».
2. **В окне 2 само:** сетка закрылась, появился оттиск.
3. «Добавить в календарь» — скачивается `.ics`, открывается в календаре в правильном поясе.
4. Кабинет: мероприятие переехало в «Время назначено».

## 5. Приглашение и гость (1 мин)

1. Окно 1: «Создать мероприятие» — форма, сводка «участники увидят 5 дней по 18 клеток».
2. Скопируйте ссылку, откройте в окне 2 после «Выйти» (или в третьем окне).
3. «Как вас зовут» → «Отметить своё время» — гость без регистрации уже в сетке.

## 6. Под капотом (1,5 мин)

- **Алгоритм:** `server/src/lib/suggest.ts` — окна длиной встречи, минимальный уровень по окну,
  1 / 0,5 / 0 баллов, обязательные отсекают окна; `cd server && npm test` — unit-тесты.
- **SQL:** тепловая карта — один запрос с `GROUP BY slot_start` и `array_agg … FILTER (WHERE level = 2)`
  (`GET /api/events/:code/heatmap`).
- **API:** Swagger `http://localhost:3000/api/docs`.
- **Модель данных:** ER-диаграмма в README.
- **Живые обновления:** Socket.IO шлёт только «изменилось», данные клиент берёт через API с проверкой прав.
- **Часовые пояса:** сетка в поясе мероприятия, `.ics` — в UTC с учётом летнего времени.
- **Качество:** 8 сквозных сценариев Playwright (`cd e2e && npm test`), DESIGN.md с измеренным контрастом.

## Возможные вопросы

- **Почему время не пересчитывается под каждого зрителя?** При разнице в несколько часов дни
  «переезжают» в сетке, и участники видят разные картинки. Сетка одна для всех, зрителю из другого
  пояса показывается подсказка с пересчётом.
- **Почему нельзя поменять даты после создания?** Отметки привязаны к клеткам; при смене сетки они
  потерялись бы. Название, описание и срок менять можно.
- **Что если два человека сохраняют одновременно?** Каждый заменяет только свои отметки в транзакции;
  чужие не затрагиваются, карта у всех обновляется по сигналу.
